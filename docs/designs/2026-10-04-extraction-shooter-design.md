# 俯视角搜打撤小游戏 — 设计文档

## Intent Contract

```
intent: 交付一个单 HTML 文件、原生 JS + Canvas 的俯视角“搜打撤”小游戏，玩家可进图搜刮宝箱、与人机 AI 交火、从撤离点带出物资存入仓库并购买子弹。
constraints:
  - 单 HTML 文件，双击 file:// 直接可玩，不引入任何游戏引擎/外部依赖
  - 全部为原生 HTML/CSS/JS + Canvas 2D，无 CDN、无构建步骤
  - 代码必须带清晰中文注释
  - 键鼠操作：WASD 移动，鼠标瞄准/射击，R 换弹，F 交互/拾取，Tab 背包，Shift 疾跑
success_criteria:
  - 能进战场、移动、瞄准、连续射击、弹匣 30 发、R 换弹、总子弹上限 210
  - 地图随机刷铜/银/金三档宝箱，靠近按 F 开箱；开箱弹窗左宝箱右背包，物品缓旋浮现，悬停物品按 F 拾取
  - Tab 打开背包，有格子上限，可丢弃物品落地并再次拾取
  - 人机 AI 会向玩家寻路靠近并开枪，子弹无限制
  - 地图存在撤离区，进入并等待 3 秒撤离成功，物资入仓库；被人机击杀则本局物资全丢
  - 仓库用 localStorage 持久化，可花游戏币购买子弹
  - 物资分白/蓝/紫/金 4 品质，宝箱品级越高越易出高级物资
risk_level: medium
```

## Verification Contract

```
verify_steps:
  - 静态检查：对 game.html 运行编辑器诊断，确保无语法/解析错误
  - 启动本地服务：python -m http.server 或等价方式托管 e:\think3，供浏览器访问
  - Playwright 运行时验证（每个模块一组断言）：
      1. 页面加载后 canvas 存在且游戏循环启动（帧计数递增）
      2. 键盘 WASD 改变玩家坐标；鼠标移动改变瞄准角度
      3. 左键按住 → 弹药数下降；归零触发换弹；R 键换弹回满至弹匣，总备弹消耗正确且不超过 210
      4. 靠近宝箱按 F → 开箱弹窗出现；悬停物品按 F → 背包物品数增加、宝箱物品减少
      5. Tab → 背包面板开合；丢弃 → 地面出现掉落物，可再拾取
      6. 进入撤离区停留 3 秒 → 状态变为撤离成功，仓库新增该局物资
      7. 玩家血量归零 → 撤离失败，本局物资清零，仓库不变
      8. 刷新页面后 localStorage 仓库数据仍在；购买子弹后备弹/游戏币变化正确
  - 人机 AI：等待若干秒，断言存在 AI 与玩家的距离随时间减小 / AI 发射了子弹
confirm: 上述断言全部通过，且在浏览器中人工试玩无明显卡顿与逻辑错误
```

## Governance Contract

```
approval_gates:
  - 设计文档确认（本文件）
  - 大体量产出（game.html）构建前的模块划分确认
rollback: 纯新增文件（docs/ + game.html + 测试脚本），删除即回滚，不影响任何既有代码
ownership: 需求方（用户）对玩法验收；实现方（Agent）对代码质量与可玩性负责
```

## Scope

| 范围 | 内容 |
| --- | --- |
| In | Canvas 渲染与游戏循环、相机、地图与碰撞、玩家移动/瞄准、射击与弹道、弹匣与备弹、宝箱刷新与开箱、背包与格子上限、物品品质系统、地面掉落与拾取、人机 AI（寻路+开枪）、撤离区与撤离流程、仓库 localStorage、购买子弹、HUD 与开箱 UI |
| Out | 联机对战、存档云同步、成就/任务系统、多种武器与配件、复杂寻路网格 A*（用简化追逐+障碍规避替代）、音效资源文件、移动端触屏适配 |

## Decisions

| # | 决策 | 选择 | 否决的替代方案 |
| --- | --- | --- | --- |
| 1 | 交付形态 | 单 HTML 文件，内联全部 CSS/JS | 多文件拆分（违背“双击即玩”）、引入引擎（过重） |
| 2 | 视觉风格 | 几何描边霓虹风（深色底 + 青/紫霓虹） | 像素素材风（需外部图）、写实贴图（需资源） |
| 3 | 操作 | WASD + 鼠标瞄准射击 | 纯键盘方向键射击 |
| 4 | AI 寻路 | 直线追逐 + 障碍贴边滑动 + 视线判断 | 完整 A* 网格（对小型地图过重） |
| 5 | 宝箱交互 | 靠近 F 开箱 → 弹窗式搜刮界面 | 直接瞬间入包（丢失“搜刮”体验） |
| 6 | 持久化 | localStorage 存仓库与游戏币 | 服务端存储（无后端需求） |
| 7 | 撤离判定 | 进入区域持续 3 秒读条 | 瞬时撤离（缺少紧张感） |

## Surface

**渲染层**：单个 `<canvas>` 承担全部游戏画面（地图、实体、粒子、准星），HUD 与开箱/背包/仓库面板用 DOM 叠加层实现，便于交互与样式。

**玩法数据**：物品定义表（名称、品质、类型、价值）；宝箱品级 → 品质权重表；仓库与游戏币序列化至 localStorage 单一 key。

**输入**：键盘按下/抬起集合 + 鼠标位置/按键集合，统一在 update 阶段读取。

**文件**：`game.html`（唯一游戏产物）；`docs/designs/`（设计文档）；测试脚本置于临时目录，不污染交付物。

## Risks & Open Questions

| 风险 | 应对 |
| --- | --- |
| 单文件体积大、状态耦合 | 按模块分区注释，状态集中在一个全局 `game` 对象，各系统纯函数优先 |
| file:// 下 localStorage 与 Canvas 表现差异 | 主要按 http 服务测试；localStorage 在 file:// 现代浏览器可用 |
| AI 数量多导致性能 | 限制同屏 AI 数量（约 6-8 个），复用对象池渲染粒子 |
| 开箱/背包 UI 与 canvas 焦点冲突 | 弹窗打开时暂停射击输入，Esc/Tab 关闭 |
| 平衡性（子弹经济/血量） | 提供常量集中配置区便于调参 |
